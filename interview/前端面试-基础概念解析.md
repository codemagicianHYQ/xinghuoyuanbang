## 一、语言与语法相关

<a id="语法糖syntactic-sugar"></a>
### 语法糖（Syntactic Sugar）

**是什么**：用更简洁、好读的写法表达另一种等价逻辑，编译或运行时会被转成更底层的实现，功能不变。

**常见例子**：
- **Vue**：`<script setup>` 是语法糖，等价于在 `setup()` 里写逻辑并 return 给模板用；`v-model` 是 `:value` + `@input` 的语法糖。
- **JS**：`class` 是「构造函数 + 原型」的语法糖；`async/await` 是 Promise + then 的语法糖；解构 `const { a } = obj`、展开 `...arr` 也是语法糖。

**面试可答**：语法糖让代码更易写易读，不增加新能力，底层还是原有机制。例如 Vue 的 `<script setup>` 本质还是 setup 函数，只是编译器帮我们做了暴露变量和 return。

---

### 闭包（Closure）

**是什么**：函数能够访问并「记住」其定义时所在作用域的变量，即使外部函数已经执行结束。

**典型场景**：防抖/节流里用闭包保存 `timer`；请求封装里回调函数引用外层的 `options`、`resolve`；模块模式里用 IIFE + 闭包做私有变量。

**面试可答**：闭包 = 函数 + 它能访问的外部变量。防抖里每次事件触发执行的是同一个返回函数，这个函数一直引用着外层的 `timer`，所以能 clear 上一次的定时器，这就是闭包的用途。

---

### var、let、const 的用法与区别

**是什么**：三者都是 JavaScript 里声明变量的方式。**var** 是 ES5 的写法；**let** 和 **const** 是 ES6 引入的，具有块级作用域。

| 特性 | var | let | const |
|------|-----|-----|-------|
| 作用域 | 函数作用域（或全局） | 块级作用域 | 块级作用域 |
| 重复声明 | 同一作用域内可重复声明 | 同一作用域内不可重复声明 | 同一作用域内不可重复声明 |
| 变量提升 | 会提升，赋值前为 undefined | 有暂时性死区（TDZ），声明前不可用 | 有暂时性死区，声明前不可用 |
| 是否可改 | 可改 | 可改 | 声明后不可重新赋值（引用类型内部属性可改） |

**注意**：`const` 声明的是「不能重新赋值」的绑定，不是「值不可变」。例如 `const obj = {}` 不能改成 `obj = {}`，但可以 `obj.name = 'x'`。项目里一般默认用 **const**，需要重新赋值时用 **let**，避免用 **var**。

**如何实现 const（面试可能问）**：真正的 const 是**语言/引擎层面**的约定，声明后该绑定不可再赋值，否则报错。若在 JS 里**模拟**「只写一次、不可改」的效果，可以：**一、用 Object.defineProperty** 在对象上定义属性，`writable: false`、`configurable: false`，则该属性不可重写；**二、用闭包** 包一个变量，只暴露 getter、在第一次 set 后不再允许修改。实际开发不需要自己实现，直接用 const 即可。

---

### 块级作用域 与 函数作用域

**函数作用域**：用 **var** 声明的变量，其作用域是「所在的函数」；在函数内任意位置声明，整个函数内都可访问（包括声明之前，值为 undefined，即变量提升）。没有块的概念，在 `if`、`for` 里声明的 var 也会泄漏到整个函数。

**块级作用域**：用 **let**、**const** 声明的变量，其作用域是「所在的块」——即一对大括号 `{}` 围成的区域，如 `if`、`for`、`while`、单独 `{}`。块外访问会报错；同一块内不能重复声明。

**典型区别**：
```js
// var：循环后 i 仍可访问，且为 3
for (var i = 0; i < 3; i++) { setTimeout(() => console.log(i), 0); }  // 3 3 3

// let：每次循环是新的块级作用域，i 各自独立
for (let i = 0; i < 3; i++) { setTimeout(() => console.log(i), 0); }  // 0 1 2
```

**词法作用域（Lexical Scope）**：指**作用域在代码书写（定义）时就已经确定**，由**函数/块定义的位置**决定，而不是由调用位置决定。JavaScript 是词法作用域：函数在定义时就会「记住」它所在的外层作用域，所以**闭包**才能访问定义时的外层变量，即使在外层函数执行完后。与之相对的是「动态作用域」（按调用时的环境找变量），JS 不是动态作用域。面试若问「什么是词法作用域」：可以答「作用域在写代码时根据定义位置就定好了，所以函数能访问它定义时的外层变量，闭包就是利用词法作用域」。

**面试可答**：var 是函数作用域、会提升、可重复声明；let/const 是块级作用域、有暂时性死区、不可重复声明。写循环、条件里的变量用 let/const 更安全，不会泄漏到外层。**词法作用域**指作用域在定义时确定，所以闭包能访问定义时的外层变量。我们项目里 ES6+ 代码基本都用 const/let，不用 var。

### ES6 相对 ES5 的新特性（概览）【面试重点】

**是什么**：ES6（ES2015）及之后的 ES6+ 在语法和 API 上相对 ES5 做了大量增强，日常说的「ES6 新特性」常包含 ES2015～ES2020+ 中常用的部分。**面试常直接问「ES6 有哪些新特性」或「ES6 和 ES5 有什么区别」**，下面按类归纳，便于按条回答。

| 类别 | ES5 常见写法 | ES6+ 新特性 | 说明 |
|------|--------------|-------------|------|
| **变量声明** | 只有 `var`，函数作用域 | **let、const**，块级作用域 | 见上「var/let/const」「块级作用域」 |
| **解构** | 手动赋值 `const a = obj.a` | **解构赋值** `const { a, b } = obj`、`const [x, y] = arr` | 对象、数组、函数参数解构，默认值 |
| **字符串** | 字符串拼接 `'a' + b + 'c'` | **模板字符串** `` `a${b}c` ``、**新增方法** `includes`、`startsWith`、`repeat` 等 | 换行、插值更方便 |
| **函数** | `function fn() {}`、回调 this 易错 | **箭头函数** `() => {}`（无自己的 this，继承外层）、**默认参数** `fn(a = 1)`、**rest** `fn(...args)` | 箭头函数不绑定 this，适合回调 |
| **数组** | for 循环、部分方法 | **扩展运算符** `[...arr]`、**Array.from**、**find/findIndex**、**includes**、**flat/flatMap** 等 | 复制、合并、查找、扁平化 |
| **对象** | 字面量 + 逐个属性 | **简写** `{ name, age }`、**计算属性名** `[key]: value`、**Object.assign**、**Object.keys/values/entries** | 写法更简洁 |
| **异步** | 回调、回调地狱 | **Promise**、**async/await**（ES2017） | 链式调用、同步写法写异步 |
| **模块** | 无标准，用 IIFE、CommonJS 等 | **import / export**（ES Module） | 静态分析、tree-shaking 友好 |
| **类与面向对象** | 构造函数 + 原型 | **class**、**extends**、**super**、**static** | 语法糖，底层仍是原型 |
| **其他** | — | **Symbol**、**Map/Set**、**for...of**、**迭代器**、**可选链** `?.`、**空值合并** `??`（ES2020） | 唯一键、去重、遍历、安全取值 |

**面试可答**：ES6 相对 ES5 我日常用得最多的是：let/const 和块级作用域、解构、模板字符串、箭头函数、Promise 和 async/await、import/export 模块化；还有 class、扩展运算符、数组新方法、对象简写等。项目里请求用 async/await，数据用解构和 const/let，组件里用 ES Module，整体都是 ES6+ 写法。**面试时可按上表分「变量、解构/字符串、函数、数组/对象、异步、模块、类、其他」几类说，重点强调 let/const、解构、箭头函数、Promise/async、模块化。**

### 解构赋值（Destructuring）

**是什么**：按「结构」从对象或数组中**一次取出**多个属性或元素，赋给变量，省去多次写 `obj.xxx` 或 `arr[i]`。

**对象解构**：`const { a, b } = obj` 从 obj 里取 a、b；**重命名** `const { a: nameA } = obj` 取 obj.a 赋给变量 nameA；**默认值** `const { a = 0 } = obj` 没有 a 时用 0；**嵌套** `const { user: { name } } = res` 取 res.user.name。  
**数组解构**：`const [x, y] = arr` 取前两个元素；**跳过** `const [, , third] = arr` 取第三个；**默认值** `const [a = 0, b = 1] = arr`；**rest** `const [first, ...rest] = arr` 第一个给 first，剩余组成数组 rest。  
**函数参数解构**：`function fn({ id, name }) { ... }`、`function fn([a, b]) { ... }` 调用时直接传对象或数组，函数里用解构后的变量。

**常见用法**：接口返回 `const { data, message } = res` 或 `const { data: { list, total } } = res`；交换变量 `[a, b] = [b, a]`；函数返回多值用数组或对象解构接收。**注意**：Vue 里 reactive 解构会丢响应式，要用 toRefs 再解构。

**面试可答**：解构是按结构从对象/数组里一次取多个值，对象用 `const { a, b } = obj`，数组用 `const [x, y] = arr`，可以默认值、重命名、rest。项目里接口返回常用 `const { data, message } = res` 拿数据和提示文案。

### CommonJS 与 ES Module（模块化）

**CommonJS**：Node.js 默认采用的模块规范，**运行时**加载，同步执行。  
- **导出**：`module.exports = xxx` 或 `exports.xxx = xxx`（注意 exports 是 module.exports 的引用）。  
- **导入**：`const xxx = require('path')`，得到的是**导出值的拷贝**（基本类型拷值，引用类型拷引用），且 require 可放在条件或函数里（动态加载）。  
- 常见于 Node 服务端、以及部分打包前的代码；浏览器端需靠 Webpack 等把 CommonJS 转成可运行的格式。

**ES Module（ESM）**：ES6 标准，**静态**模块，在编译/解析阶段就能确定依赖关系。  
- **导出**：`export default xxx`、`export { a, b }`。  
- **导入**：`import xxx from 'path'`、`import { a, b } from 'path'`，得到的是**只读引用**（不是拷贝），运行到用时才取值。  
- 支持 **tree-shaking**（打包时去掉未用到的导出）；import 一般写在顶层，不能放在 if 里（静态结构），动态加载用 `import()` 返回 Promise。

**对比小结**：

| 维度 | CommonJS | ES Module |
|------|----------|-----------|
| 语法 | require / module.exports | import / export |
| 加载时机 | **运行时**，同步 | **静态分析**，可静态优化 |
| 加载方式 | 可动态 require(path) | 顶层 import，动态用 import() |
| 导出值 | **拷贝**（值拷贝或引用拷贝） | **只读引用**， live binding |
| 典型环境 | Node 默认、老项目 | 浏览器 + Node（type: module）、Vite/打包后 |

**面试可答**：CommonJS 用 require/module.exports，运行时加载、同步，导出的是拷贝；ES Module 用 import/export，静态结构、便于 tree-shaking，导出是只读引用。我们前端项目用 ES Module（import/export），Node 后端常见 require；若被问「两种模块区别」可从加载时机、是否静态、拷贝 vs 引用 这几条说。

### for...in 与 for...of 的区别

**for...in**：遍历对象的**可枚举属性名**（包括原型链上的），遍历的是 **key**；遍历数组时得到的是**下标**（字符串形式的索引）。不适合遍历数组（会带出原型上的属性、顺序不保证），适合遍历普通对象键。

**for...of**：遍历**可迭代对象**的**值**（如数组元素、Map/Set 值、字符串字符），遍历的是 **value**。不能直接遍历普通对象（对象默认不可迭代），适合数组、类数组、Map、Set、字符串等。

**面试可答**：for...in 遍历键（对象属性、数组下标），for...of 遍历值（数组元素等）。遍历数组用 for...of 或 forEach；遍历对象用 for...in 或 Object.keys/entries。

---

### 键值对（对象与 Map）

**键值对**：一组「**键（key）** + **值（value）**」的对应关系，通过键可以存取对应的值。在 JavaScript 里常见两种形式：

**1. 对象（Object）**  
- 对象的**属性名**就是**键**，**属性值**就是**值**，如 `{ id: 1, name: '任务' }` 里 `id`、`name` 是键，`1`、`'任务'` 是值。  
- 键一般是**字符串**（或 **Symbol**），非字符串会转成字符串；值可以是任意类型。  
- **遍历键值对**：**Object.keys(obj)** 取所有键、**Object.values(obj)** 取所有值、**Object.entries(obj)** 取 `[键, 值]` 数组；也可用 **for...in** 遍历键（注意会包含原型链上的可枚举属性）。

**2. Map**  
- **Map** 是 ES6 的「键值对集合」，键可以是**任意类型**（对象、函数等），不限于字符串；有序（插入顺序）。  
- 常用：`map.set(key, value)`、`map.get(key)`、`map.has(key)`、`map.delete(key)`；遍历用 `map.forEach` 或 `for (const [key, value] of map.entries())`。

**和对象的区别**：对象键一般是字符串/Symbol，Map 键可任意类型；对象有原型链，Map 更干净；频繁增删键值对、需要「非字符串键」时用 Map 更合适。

**面试可答**：键值对就是 key 和 value 的对应，JS 里常用**对象**（属性名当键、属性值当值）和 **Map**（键可任意类型）。遍历对象键值用 Object.keys/values/entries 或 for...in；Map 用 forEach 或 entries()。接口返回的 JSON 本质就是键值对，我们常 `Object.keys()`、`Object.entries()` 做遍历或转成数组处理。

### 箭头函数与普通函数的区别

| 对比 | 普通函数 function | 箭头函数 => |
|------|-------------------|-------------|
| this | 谁调用指向谁，可被 call/apply/bind 改 | 继承定义时外层 this，不可改 |
| arguments | 有 | 无，用 rest ...args 代替 |
| 作为构造函数 new | 可以 | 不可以 |
| 原型 prototype | 有 | 无 |

**面试可答**：箭头函数没有自己的 this，适合回调和数组方法里用，避免 this 指向错；要做构造函数或需要 arguments 时用普通函数。项目里请求回调、map/filter 里用箭头函数保持 this 指向组件实例。

### 原型与原型链【面试常考】

**原型（prototype）**：每个**函数**都有一个 **prototype** 属性，指向一个对象，这个对象是「由该函数作为构造函数 new 出来的实例」的**原型对象**。在原型对象上挂属性和方法，实例就能通过「原型链」访问到，实现共享、节省内存。

**__proto__**：每个**对象**（包括函数）都有一个 **__proto__**（现规范推荐用 `Object.getPrototypeOf(obj)`），指向其**构造函数的 prototype**。例如 `const obj = {}`，obj.__proto__ 指向 Object.prototype；`function F() {}`，F.prototype 是原型对象，`const f = new F()` 时 f.__proto__ === F.prototype。

**原型链**：访问对象属性时，先找**自身**，没有则沿 **__proto__** 往上一层找，直到 **Object.prototype**，再往上就是 null。这条「对象 → 其 __proto__ → 再 __proto__ → … → null」就是**原型链**。所以 for...in 会遍历到原型链上的可枚举属性；自己挂的属性在对象上，继承的在上层原型上。

**constructor**：原型对象上有 **constructor** 属性，指回构造函数，如 `F.prototype.constructor === F`。instanceof 的原理就是沿实例的 __proto__ 链看有没有出现某构造函数的 prototype。

**ES6 class**：class 是「构造函数 + 原型」的语法糖，extends 继承底层仍是设置原型链（子类 prototype.__proto__ 指向父类 prototype）。所以理解原型链有助于理解 class 和继承。

**面试可答**：函数有 prototype，实例有 __proto__ 指向构造函数的 prototype；访问属性时先自身再沿 __proto__ 往上找，这条链就是原型链；for...in 会遍历到原型链上的可枚举属性，所以遍历数组一般用 for...of 或 forEach。class 是语法糖，底层还是原型。

### 形参与实参

**形参（parameter）**：函数**定义时**声明的参数，写在函数名后面的括号里，如 `function fn(a, b)` 里的 `a`、`b`。用来接收调用时传入的值。

**实参（argument）**：函数**调用时**实际传入的值，如 `fn(1, 2)` 里的 `1`、`2`。会按顺序一一赋给形参。

**注意**：形参和实参个数可以不一致。实参多于形参时，多出的在普通函数里可通过 **arguments** 访问（箭头函数没有 arguments，用 rest `...args`）。实参少于形参时，未传入的形参为 **undefined**，可用**默认参数**如 `function fn(a, b = 0)` 兜底。**rest 参数** `...rest` 可把「剩余实参」收成数组。

**面试可答**：形参是定义时的占位符，实参是调用时传进去的值，按顺序对应。多传的用 arguments 或 ...rest 取，少传的形参为 undefined，常用默认参数处理。

### JS 数组常用方法（概览）

**会改变原数组**：**push**（尾加）、**pop**（尾删）、**unshift**（头加）、**shift**（头删）、**splice**（指定位置增删改）、**reverse**（反转）、**sort**（排序，默认按字符串排，可传比较函数）。

**不改变原数组，返回新数组或新值**：**slice**（截取一段，可浅拷贝）、**concat**（拼接）、**map**（遍历并返回新数组）、**filter**（过滤出满足条件的）、**reduce**（归并为单一值）、**find**（找第一个满足条件的元素）、**findIndex**（找第一个满足条件的下标）、**includes**（是否包含某值）、**flat**（扁平化）、**join**（用分隔符拼成字符串）。

**map(callback)**：遍历数组每个元素，对每个元素执行回调，**回调的返回值**组成一个**新数组**并返回，**不改变原数组**。回调参数常用 `(item, index, array)`（当前元素、下标、原数组）。典型用法：接口 list 转成组件需要的结构，如 `list.map(item => ({ id: item.id, name: item.name }))`；或取某一列 `ids = list.map(item => item.id)`。**和 forEach 区别**：map **有返回值**且为新数组，forEach 无返回值、只做遍历和副作用。

**遍历**：**forEach(callback)** — 对每个元素执行一次回调，**无返回值**（返回 undefined）。回调参数常用 `(item, index, array)`，即当前元素、下标、原数组。**注意**：不能像 for 那样 break/continue，回调里 return 只相当于「跳过当前这一次」，不会终止遍历；若需要中途退出用 for/for...of。**和 map 区别**：map 返回新数组（每个元素经回调映射成新值），forEach 只做「遍历 + 副作用」，不返回新数组。  
**判断**：**Array.isArray**（是否为数组）、**some**（是否有元素满足条件）、**every**（是否全部满足）。

项目里对接口返回的 list 常用 **map** 转成组件需要的结构、**filter** 筛数据、**forEach** 或 for...of 遍历；**slice**、**concat**、展开 `[...arr]` 做浅拷贝；**includes**、**find** 做存在性/查找。

**面试可答**：增删用 push/pop/shift/unshift/splice；遍历映射用 map，过滤用 filter，归并用 reduce；不改变原数组的用 slice、map、filter、concat；要判断是否数组用 Array.isArray。

### Promise 与 async/await（异步编程核心）

**Promise 是什么**：表示一个「未来才会得到结果」的异步操作，有三种状态：**pending（进行中）**、**fulfilled（已成功）**、**rejected（已失败）**。创建时传入的函数会马上执行，并在合适的时候调用 `resolve(value)` 或 `reject(error)`。

- **then / catch / finally**：`promise.then(onFulfilled).catch(onRejected).finally(onFinally)`；then 返回新的 Promise，可链式调用；catch 统一处理错误；finally 无论成功失败都会执行，适合关 loading。
- **常用静态方法**：  
  - `Promise.all([p1, p2])`：**并发多个 Promise**，全部成功才成功，有一个失败就整体失败（进入 catch），适合「缺一不可」的并发请求。  
  - `Promise.race([p1, p2])`：谁先完成用谁的结果。  
  - `Promise.allSettled([p1, p2])`：无论成功失败都返回每个 Promise 的状态与结果，适合「希望知道每个结果」的场景。

**async/await 是什么**：基于 Promise 的**语法糖**，用同步写法写异步代码。`async` 函数默认返回一个 Promise；在其中用 `await` 等待 Promise 结果，写起来更直观，需要用 try/catch 包住做错误处理。

**面试可答**：Promise 解决回调地狱，有 pending/fulfilled/rejected 三态，靠 then/catch/finally 链式处理，Promise.all 用于并发请求。async/await 是 Promise 的语法糖，让异步代码像同步一样写，我们项目里请求封装返回 Promise，业务里普遍用 async/await + Promise.all 并发拉任务列表和用户信息。

### 宏任务与微任务（事件循环）【面试常考】

**事件循环（Event Loop）**：JavaScript 是单线程的，异步任务通过「事件循环」调度。每轮循环大致是：执行一个**宏任务** → 清空当前**微任务队列** → 若有需要则渲染 → 再取下一个宏任务，如此往复。

**宏任务（Macro Task）**：由宿主（浏览器/Node）发起的任务，一次事件循环执行一个（或一类）。常见：**script 整体代码**、**setTimeout**、**setInterval**、**I/O**、**UI 渲染**（浏览器）、**setImmediate**（Node）等。

**微任务（Micro Task）**：在**当前宏任务执行完后、下一个宏任务之前**全部执行完。常见：**Promise.then / catch / finally** 的回调、**queueMicrotask**、**MutationObserver**（浏览器）、**process.nextTick**（Node，比微任务还早）等。

**执行顺序要点**：同一轮里**微任务先于下一个宏任务**。例如：  
`setTimeout(() => console.log(1), 0); Promise.resolve().then(() => console.log(2)); console.log(3);`  
输出顺序是 **3 → 2 → 1**：先执行同步代码输出 3；当前宏任务结束，清空微任务队列输出 2；再执行 setTimeout 的宏任务输出 1。

**面试可答**：JS 单线程靠事件循环执行异步；宏任务有 setTimeout、setInterval、I/O 等，微任务有 Promise.then、queueMicrotask 等；每轮循环执行一个宏任务后会把当前所有微任务跑完，再执行下一个宏任务，所以 Promise 回调总在「同轮」里排在 setTimeout 之前。能说清「微任务先于下一轮宏任务」并举一个 3→2→1 的例子即可。

### 防抖（Debounce）与 节流（Throttle）

| 概念 | 含义 | 典型场景 |
|------|------|----------|
| **防抖** | 事件触发后等待一段时间，若期间再次触发则重新计时，直到「安静」了指定时间才执行一次。 | 搜索框输入、窗口 resize 后算尺寸、表单校验（停输后再校验）。 |
| **节流** | 在一段时间内无论触发多少次，只执行一次，到时间后再触发再执行。 | 滚动加载、按钮防重复点击、滚动条位置计算。 |

**区别**：防抖是「停下来了才执行」；节流是「每隔一段时间执行一次」。

### 深拷贝与浅拷贝（面试高频）

**是什么**：复制一个对象或数组时，**浅拷贝**只复制「第一层」：基本类型拷的是值，引用类型（对象、数组）拷的是**引用**，所以改拷贝后的对象里的嵌套对象，会影响原对象。**深拷贝**是「递归复制所有层级」，新对象和原对象完全独立，改一方不影响另一方。

| 对比 | 浅拷贝 | 深拷贝 |
|------|--------|--------|
| 复制深度 | 只复制第一层 | 递归复制所有层级 |
| 嵌套对象/数组 | 仍指向原引用，改则两边都变 | 全新对象，互不影响 |
| 典型场景 | 只想复制一层、或确定没有嵌套 | 需要完全独立的副本（如表单初始值备份、避免修改原数据） |

**浅拷贝常见写法**：
- `Object.assign({}, obj)`、`{ ...obj }`（对象）
- `[...arr]`、`arr.slice()`、`arr.concat([])`（数组）

**深拷贝常见写法与注意点**：
1. **JSON.parse(JSON.stringify(obj))**：简单好用，但有局限：**函数、undefined、Symbol** 会丢失；**Date** 会变成字符串；**正则、Map、Set** 等会变成空对象；**循环引用**会报错。只适合纯数据对象（无函数、无循环引用）。
2. **手写递归**：遍历属性，基本类型直接赋，引用类型递归深拷贝；要处理数组、Date、正则、循环引用（用 Map 存已访问对象）等，代码量稍大但可控。
3. **lodash 的 cloneDeep**：兼容多种类型和循环引用，生产常用。
4. **structuredClone(value)**（现代浏览器、Node 17+）：原生深拷贝，支持多数内置类型和循环引用，不支持函数。

**面试可答**：浅拷贝只复制第一层，嵌套的引用类型还是同一份，改会联动；深拷贝是全部层级都复制成新对象，互不影响。浅拷贝用展开或 Object.assign 就行；深拷贝简单数据用 JSON 方案，有函数或循环引用就用 lodash cloneDeep 或手写递归，现代环境也可以用 structuredClone。项目里需要「备份一份数据避免被修改」时会用深拷贝，比如表单初始值、列表项编辑前先拷一份。

## 二、Vue / 前端框架相关

### 响应式（Reactive）

**是什么**：数据变化时，依赖这些数据的视图或逻辑会自动更新，无需手写「改数据再改 DOM」。

**实现方式**：Vue2 用 `Object.defineProperty` 劫持属性；Vue3 用 `Proxy` 代理对象，可监听新增/删除属性和数组下标。核心都是「依赖收集 + 派发更新」。

**面试可答**：我们说的「数据驱动」「响应式」，就是指改 data/ref/reactive，视图自动跟着变，不用自己操作 DOM。

---

### Proxy 与 handler（target、key、value）【与 Vue3 响应式相关】

**Proxy 是什么**：ES6 内置的**代理**，用 `new Proxy(target, handler)` 创建一个对 `target` 的代理对象，对代理对象的读写会经过 `handler` 里的**陷阱函数**（如 `get`、`set`），可在其中做依赖收集、派发更新等，Vue3 的 reactive 就是这样实现的。

**handler 里常用陷阱与参数**：

- **get(target, key, receiver)**  
  - **target**：被代理的**原始对象**。  
  - **key**：当前访问的**属性名**（字符串或 Symbol）。  
  - **receiver**：代理对象本身（或继承链上的代理），一般用 `Reflect.get(target, key, receiver)` 保证 this 正确。  
  - 在 Vue3 里，get 里根据 key 做**依赖收集**（把当前运行的 effect 记到该 key 的依赖里）。

- **set(target, key, value, receiver)**  
  - **target**：被代理的**原始对象**。  
  - **key**：被设置的**属性名**。  
  - **value**：要设置的**新值**。  
  - **receiver**：代理对象（或继承链上的代理）。  
  - 在 Vue3 里，set 里先对 target 赋值（或 `Reflect.set`），再根据 key **派发更新**（通知依赖该 key 的 effect 重新执行）。

**面试可答**：Proxy 是 ES6 的代理，`new Proxy(target, handler)`；get 里 **target** 是原对象、**key** 是属性名，set 里多一个 **value** 表示新值。Vue3 用 Proxy 做响应式时，在 get 里收集依赖，在 set 里触发更新。receiver 一般和 `Reflect.get/set` 配合保证在继承场景下 this 正确。

---

### Promise 与 Proxy 的联系（面试可能问）

**区别**：**Promise** 管**异步**（未来结果、then/catch、微任务）；**Proxy** 管**对象代理**（拦截 get/set 等，Vue3 响应式）。两者职责不同，都是 ES6 的重要特性。

**联系**（在 Vue3 响应式里的交汇）：  
- Vue3 用 **Proxy** 拦截 reactive 对象的 get/set，在 set 里**派发更新**（通知依赖该数据的 effect 重新执行）。  
- 这些更新不会立刻执行，而是被**放入调度器**，通常用 **微任务**（如 `Promise.resolve().then(...)` 或 `queueMicrotask`）延后到当前同步代码和当前宏任务之后执行，从而**合并同一轮里的多次修改**，避免重复渲染。  
- **Promise.then** 的回调也是**微任务**，和「Proxy 触发的更新任务」在**同一套事件循环、同一微任务队列**里。所以可以简单说：**Proxy 负责「拦截变更、派发更新」，Promise（微任务）负责「把更新任务排队、在合适的时机执行」**；在 Vue3 里二者通过「微任务」连在一起。

**面试可答**：Promise 管异步、Proxy 管对象代理；在 Vue3 里 Proxy 做响应式拦截，set 时派发更新，更新会被放进微任务队列（和 Promise.then 同一队列），所以两者在「微任务调度」上有交汇——Proxy 发现变化，微任务负责把 DOM 更新推到下一轮执行。

### Vue2 与 Vue3 区别及 Vue3 改进（汇总）

**一、响应式**  
| Vue2 | Vue3 |
|------|------|
| `Object.defineProperty` 劫持已有属性 | `Proxy` 代理整个对象 |
| 新增/删除属性监听不到，需 Vue.set | 支持新增、删除属性 |
| 数组下标、length 监听不完整 | 数组下标等完整监听 |
| 递归遍历初始化，性能较差 | 懒代理，按需代理，性能更好 |

**二、API 与写法**  
- **Vue2**：选项式 API（data、methods、computed、watch、mounted 等分块写）。  
- **Vue3**：推荐**组合式 API**（setup / `<script setup>` + ref、reactive、computed、onMounted 等），按功能组织逻辑，易复用；仍兼容选项式。

**三、生命周期**  
- Vue2：beforeCreate、created、beforeMount、mounted、beforeUpdate、updated、**beforeDestroy**、**destroyed**。  
- Vue3 组合式：无 beforeCreate/created（setup 等价于二者之间）；挂载/更新/卸载用 **onBeforeMount、onMounted、onBeforeUpdate、onUpdated、onBeforeUnmount、onUnmounted**（destroy 改为 unmount）。

**四、模板与组件**  
- **多根节点（Fragment）**：Vue3 单文件组件可有多个根节点，Vue2 只能一个。  
- **Teleport**：Vue3 内置，可把内容渲染到 DOM 其他位置（如 body 下弹窗）。  
- **v-model**：Vue2 一个组件只能一个 v-model；Vue3 可多个，如 `v-model:title`、`v-model:visible`。  
- **v-if 与 v-for 优先级**：Vue2 中 v-for 高于 v-if；Vue3 中 v-if 高于 v-for，避免同一元素上混用时的歧义。

**五、移除与废弃**  
- Vue3 移除：**过滤器（filter）**，用方法或计算属性代替；**$on、$off、$once**（事件总线），用外部库或 provide/inject 等替代。  
- **$children** 移除，用 ref 取子组件实例。  
- 部分内置组件/API 更名或替换（如 transition 类名、functional 组件等）。

**六、性能与体积**  
- Vue3 源码 **Tree-shaking** 友好，未用到的 API 不会打进包，体积更小。  
- 虚拟 DOM 与 diff 优化（静态提升、事件缓存等），渲染性能更好。  
- **Composition API** 便于逻辑复用（自定义 hooks），减少重复代码。

**七、其他**  
- **TypeScript** 支持更好，Vue3 用 TS 重写。  
- **defineAsyncComponent**、**Suspense** 支持异步组件与加载态。  
- 状态管理推荐 **Pinia**（Vue3 官方推荐），替代 Vuex 的简化方案。

**面试可答**：可从响应式（Proxy 更完整、性能更好）、组合式 API、生命周期命名变化、多根节点与 Teleport、移除 filter 与 $on、性能与 Tree-shaking、TypeScript 与 Pinia 等几条里挑熟悉的说，结合项目（如管理后台用 Vue3 + 组合式）即可。详见《吉利前端面试-基于简历与星火园帮》Q9、响应式总结表、Q9-1、Q12-1。

### ref 与 reactive（Vue 3）

**ref**：Vue 3 里用来包一层「响应式引用」的 API，可以包任意类型（数字、字符串、布尔、对象、数组）。在 **script 里**读写要用 `.value`（如 `count.value = 1`）；在**模板里**会自动解包，直接写变量名即可（如 `{{ count }}`）。常用于：基本类型、需要整体替换的引用（如数组、对象）、以及**拿 DOM 或子组件实例**（在模板里给元素或组件加 `ref="xxx"`，script 里用 `const xxx = ref(null)`，挂载后 `xxx.value` 就是该 DOM 或组件实例）。

**reactive**：只能包**对象**，包完后直接访问属性即可，不需要 `.value`。解构会丢响应式，要用 toRefs 才能解构后仍响应。一般表单对象、筛选条件等用 reactive；简单值和「要整体替换」的用 ref。

**面试可答**：ref 包任意类型，script 里用 .value，模板里自动解包；还可以给元素或组件绑 ref 拿 DOM/组件实例。reactive 只包对象，直接访问属性。项目里表单用 reactive，loading、列表数据、DOM 引用用 ref。

### 虚拟 DOM（Virtual DOM）与 diff

**是什么**：用 JavaScript 对象描述真实 DOM 树的结构（如 `{ tag: 'div', props: {}, children: [] }`）。数据变化时先生成新虚拟 DOM，和上一次做 **diff（对比）**，算出最小变更再一次性更新真实 DOM。

**为什么要用**：减少直接操作真实 DOM 的次数，降低重排/重绘；方便跨平台（同一套描述可渲染到不同环境）；配合组件化、声明式写法更自然。

**key 的作用**：在列表里给节点一个稳定唯一的 key，diff 时能正确匹配「新节点对应哪个旧节点」，避免误复用、状态错乱，列表增删排序时尤其重要。

---

### SPA（单页应用，Single Page Application）

**是什么**：整个应用只有一个 HTML 页面，首次加载后通过 JS 根据路由切换要展示的视图，不再向服务器请求新的 HTML，数据通过接口获取。

**和传统多页的区别**：传统每点一个链接就请求新页面、整页刷新；SPA 只换「视图层」，路由 + 组件切换 + 接口拉数，体验更顺，前后端分离更彻底。

---

### 声明式 与 命令式

**命令式**：一步步告诉程序「怎么做」（先取 DOM、再改 innerHTML、再加类名……）。  
**声明式**：描述「要什么结果」（数据是什么，视图就展示什么），具体怎么做交给框架。  
Vue 的 template + data 就是声明式：我们写的是「状态和结构」，更新 DOM 由框架完成。

---

<a id="vue-常用指令v-bindv-htmlv-ifv-show-等"></a>
### Vue 常用指令（v-bind、v-html、v-if、v-show 等）

**v-bind**（可简写为 `:`）：把**数据绑定到元素的属性**上，属性值随数据变化。例如 `:href="url"`、`:class="{ active: isActive }"`、`:style="{ color: textColor }"`。不写 v-bind 时属性是静态字符串；加了 v-bind 后引号里是 JS 表达式，可绑定变量、对象、数组等。

**v-html**：把**字符串当作 HTML 渲染**到元素内部，相当于设置 `innerHTML`。例如 `v-html="richContent"` 会把 `richContent` 里的标签解析成真实 DOM。**注意**：只用于可信内容，用户输入或接口返回的富文本若未做过滤就交给 v-html，可能造成 **XSS（跨站脚本）**，需要先做转义或白名单过滤。

**v-if / v-else / v-else-if**：**条件渲染**，为 false 时节点不会出现在 DOM 里，切换会销毁和重建。适合「很少切换」或「初始就不展示」的场景。

**v-show**：通过切换 **display** 显隐，节点始终在 DOM 里。适合**频繁切换**（如 Tab、折叠面板）。

**v-model**：**双向绑定**，常用于表单控件（input、textarea、select），本质是 `:value` + `@input` 的语法糖；Vue3 组件上可写多个，如 `v-model:title`、`v-model:visible`。

**v-for**：列表渲染，需配合 **key**（建议用唯一 id），便于 diff 时正确复用节点。

**面试可答**：v-bind 绑属性（`:xxx="表达式"`）；v-html 把字符串当 HTML 渲染，要防 XSS；v-if 条件为假时节点不存在，v-show 只改 display；v-model 做表单双向绑定。项目里富文本展示若来自后台且已做安全过滤，可用 v-html；属性绑定大量用 `:class`、`:style`、`:src` 等。

---

### Vue 中的传参方式（组件传参 + 路由传参）

**组件间传参**：  
- **props**：父 → 子，父组件通过属性把数据传给子组件，子组件用 props 接收。  
- **emit**：子 → 父，子组件 `$emit('事件名', 参数)`，父组件 `@事件名="处理函数"` 接收。  
- **provide / inject**：祖先 → 后代，跨层级注入，祖先 provide、后代 inject 取。  
- **Vuex / Pinia**：全局状态，多组件共享，适合用户信息、 token、主题等。  
- **本地存储**：localStorage / sessionStorage，配合 Vuex 做持久化或简单跨页带参。

**路由传参**：  
- **query**：参数拼在 URL 上（如 `/detail?id=1&type=2`），用 `$route.query.id` 或 `useRoute().query.id` 取，刷新不丢，适合列表点进详情的 id、筛选条件等。  
- **params**：命名路由的 params（如 `name: 'Detail', params: { id: 1 }`），用 `$route.params.id` 取，刷新可能丢（看是否用动态路由），Vue Router 4 中若用 path 跳转不会带 params。  
- **动态路由**：路由配置 `/task/:id`，跳转 `/task/123`，用 `$route.params.id` 取 123。

**面试可答**：组件传参用 props 下传、emit 上传，跨层级用 provide/inject 或 Vuex；路由传参用 query（URL 可见、刷新不丢）或动态路由 params。项目里列表进详情用 query 或动态路由传 id，组件间用 props/emit 和 Vuex 配合。详见《吉利前端面试-基于简历与星火园帮》Q10、Q10-1。

---

### Vue Router（前端路由）【面试常问】

**作用**：在 SPA 里根据 **URL 路径** 切换要展示的组件，不向服务器要新页面，由前端自己维护「路径 ↔ 组件」的映射。

**常用 API**：  
- **useRouter()** / **useRoute()**（Vue3 组合式）：router 做跳转（push、replace、go），route 取当前路由信息（path、query、params）。  
- **router-link**：声明式导航，`<router-link to="/tasks">`，点击不刷新整页。  
- **编程式导航**：`router.push('/detail?id=1')`、`router.push({ name: 'Detail', params: { id: 1 } })`、`router.replace(...)`。  
- **路由配置**：path、name、component、children（嵌套）、meta（如用于权限、标题）等。

**两种模式**：  
- **hash**：URL 带 `#`，如 `/index.html#/tasks`，改 `location.hash` 不发请求，兼容性好；Vue Router 用 `createWebHashHistory()`。  
- **history**：用 `history.pushState`/`replaceState`，URL 无 `#`；刷新或直接打开某路径时请求会到服务器，需服务器把该路径回退到 index.html（如 Nginx 的 try_files），否则 404；Vue Router 用 `createWebHistory()`。

**路由懒加载**：用动态 import 把组件写成异步，如 `component: () => import('@/views/Task.vue')`，首屏只加载当前匹配的组件，其它路由的组件进入时再加载，减小首包体积。

**导航守卫**：在进入/离开路由前做校验或逻辑，如 **beforeEach**（全局前置）：检查 token，未登录则跳登录页；**beforeEnter**（单路由）、**beforeRouteLeave**（组件内）等。常用于登录鉴权、标题设置、离开前确认。

**面试可答**：Vue Router 做 SPA 的前端路由，根据 URL 渲染对应组件；常用 useRouter/useRoute、router-link、编程式 push/replace；hash 模式不改发请求、history 要服务器配 fallback；路由懒加载用 `() => import(...)` 减小首屏；鉴权常用 beforeEach 里判断 token 再 next() 或跳登录。详见《吉利前端面试-基于简历与星火园帮》Q10-1（传参）、Q16-15～Q16-17（SPA、hash/history、首屏优化）。

---

### Vuex 与 Pinia（状态管理）【面试常问】

**作用**：做**全局状态管理**，多组件共享同一份数据（如用户信息、token、主题），避免层层 props 或事件总线混乱。

**Vuex（Vue2 时代主流）**：  
- **结构**：**state**（数据）→ **getters**（派生）→ **mutations**（同步改 state，唯一改 state 的入口）→ **actions**（异步，里面对 commit 调 mutation）。  
- **特点**：严格单向数据流，改 state 必须通过 mutation，便于追踪；模块用 **modules** 拆，但命名空间、嵌套稍繁琐；和 Vue2 搭配多，Vue3 也能用。

**Pinia（Vue3 官方推荐）**：  
- **结构**：用 **defineStore** 定义 store，里面直接写 **state**、**getters**、**actions**；**没有 mutation**，在 action 里或组件里**直接改 state**（也可以约定只在 action 里改，看团队规范）。  
- **特点**：API 更简单，一个 store 一个 defineStore，天然按 store 拆分；**TypeScript** 支持好；和 Composition API 搭配自然（useXxxStore()）；Vue3 官方推荐，可视为 Vuex 5 的替代。

**对比小结**：

| 维度 | Vuex | Pinia |
|------|------|--------|
| 改 state | 必须通过 **mutation**（同步） | **无 mutation**，可直接改 state 或在 action 里改 |
| 异步 | **actions** 里 dispatch/commit | **actions** 里直接改 state 或调接口后改 |
| 模块化 | **modules** + 命名空间 | 多个 **defineStore**，每个即一个「模块」 |
| TS / Vue3 | 能用，配置稍多 | 官方推荐，TS 友好、和 Composition API 契合 |
| 适用 | Vue2 项目、老项目 | Vue3 新项目首选 |

**面试可答**：Vuex 用 state + mutations + actions，改 state 必须通过 mutation；Pinia 没有 mutation，state 可直接改或只在 action 里改，API 更简洁，Vue3 官方推荐，TS 支持也好。我们小程序是 Vue2 用 Vuex 存用户信息和 token；若新项目用 Vue3 会优先 Pinia。详见《吉利前端面试-基于简历与星火园帮》Q10、Q10-1a。

## 三、CSS 相关

<a id="盒模型box-model"></a>
### 盒模型（Box Model）

**是什么**：一个元素占用的空间由 **content（内容）**、**padding（内边距）**、**border（边框）**、**margin（外边距）** 组成。

**content-box / border-box**：
- **content-box**（默认）：`width`/`height` 只算内容区，加 padding 后总宽会变。
- **border-box**：`width`/`height` 已包含 padding 和 border，设了宽高后加 padding 不会把盒子撑大。布局时常用 `box-sizing: border-box` 便于计算。

**position 与 relative 的定位参照**：**relative** 是相对**自身在文档流中的原始位置**进行偏移，原占位保留。**absolute** 相对「最近一个 position 不为 static 的祖先」定位。面试若问「relative 是基于什么定位」：答「相对自身原来位置偏移」。详见《吉利前端面试-基于简历与星火园帮》Q16-11。

---

### BFC（块级格式化上下文，Block Formatting Context）

**是什么**：一块独立的渲染区域，内部布局与外部隔离，内部元素不会影响外部布局。

**常见触发条件**：`overflow: hidden`、`float` 非 none、`position: absolute/fixed`、`display: inline-block/flex/grid` 等。

**应用**：清除浮动（父元素塌陷）、防止 margin 折叠、两栏自适应（一侧 float，另一侧形成 BFC 与浮动不重叠）。

---

### Flex 两子元素放父元素两侧

父元素 `display: flex`，要让两个子块分别在左右两侧：**方式一** `justify-content: space-between`，中间自动留空。**方式二** 左侧块不动，右侧块 `margin-left: auto`，把右侧推到最右。导航栏「左边 logo、右边用户」常用这两种。

---

### 去除 / 隐藏滚动条（保留滚动）

**完全去掉滚动条**：`overflow: hidden`（会禁止滚动，慎用）。**保留滚动但隐藏滚动条**：`overflow: auto` 或 `overflow-y: scroll` 配合 `scrollbar-width: none`（Firefox）、`-webkit-scrollbar { display: none }` 或 `width: 0; height: 0`（Chrome 等）。移动端部分容器可用 `-webkit-overflow-scrolling: touch` 保持顺滑。

---

### 重排（Reflow）与 重绘（Repaint）

| 概念 | 含义 |
|------|------|
| **重排** | 元素几何属性（宽高、位置、边距等）或布局结构变化，浏览器重新计算布局。成本高，可能引发连锁重排。 |
| **重绘** | 颜色、阴影、可见性等变化，不改变布局，只重新绘制。成本相对较低。 |

**优化思路**：少改触发布局的属性；动画多用 `transform`、`opacity`（只触发合成）；批量改 DOM；虚拟列表减少节点数。

<a id="四网络与后端相关"></a>
## 四、网络与后端相关

<a id="nodejs-与-express-概览"></a>
### Node.js 与 Express 概览

**Node.js**：基于 Chrome V8 的 JavaScript 运行环境，让 JS 可在服务器端运行，常用于写后端 API、工具脚本。特点：单线程 + 事件循环、异步 I/O、npm 生态丰富。

**Express**：Node 上最常用的 Web 框架，用来快速搭建 HTTP 服务、提供 RESTful API。核心概念：**中间件**（按顺序执行的 (req, res, next) 函数）、**路由**（按方法和路径匹配到具体处理函数）。

**Express 常用 API**：  
- `const app = require('express')()` 创建应用。  
- `app.use(中间件)` 或 `app.use('/path', 中间件)` 挂载全局或路径级中间件。  
- `app.use(express.json())`、`app.use(express.urlencoded({ extended: true }))` 解析 JSON 和表单 body。  
- `const router = express.Router()` 创建子路由；`router.get/post/put/delete(path, handler)` 定义路由；`app.use('/api', router)` 挂到某前缀下。  
- `app.listen(port)` 监听端口。  
- 在路由/控制器里用 `req`、`res` 取请求、发响应；出错时 `next(err)` 交给错误处理中间件（四参数 `(err, req, res, next)`）。

**请求链路**：请求进入 → 依次经过中间件（如 CORS、body 解析）→ 匹配到某路由 → 路由里可能再经过鉴权中间件 → 控制器里从 req 取参数、查库、用 res 返回。

**面试可答**：Node 是服务端 JS 运行环境，Express 是上面的 Web 框架，用中间件 + 路由组织接口；我们项目里 Node + Express 提供 RESTful API，中间件处理 CORS、body、JWT 鉴权，路由按模块拆（auth、user、task 等），详见下面「中间件」「req 与 res」及《吉利前端面试-基于简历与星火园帮》Q25、Q25-1、Q25-2。

---

### 中间件（Middleware）

**是什么**：在「请求进入」和「最终响应」之间执行的一层逻辑，通常是一个函数 `(req, res, next)`，可以改 req/res、做校验、调用 `next()` 交给下一个中间件。

**常见用途**：CORS、解析 body、鉴权（验 JWT）、日志、错误统一处理。Express 里按顺序挂载，请求依次经过各中间件再到路由处理函数。

---

### req 与 res（Express 的请求与响应对象）

**req（request）**：表示当前这次 HTTP 请求，常用属性/方法：**req.url**、**req.method**（GET/POST 等）、**req.headers**（请求头，如 req.headers.authorization、req.headers.token 取 token）、**req.query**（URL 查询参数，如 `?id=1` 得到 req.query.id）、**req.body**（请求体，需先经过 express.json() 等解析）、**req.params**（路由参数，如 `/user/:id` 得到 req.params.id）。鉴权后会把用户信息挂到 **req.user**，后续路由里直接用 req.user。

**res（response）**：表示要返回给客户端的响应，常用：**res.status(200)** 设状态码、**res.json({ data })** 发 JSON、**res.send()** 发内容、**res.redirect()** 重定向。例如 `res.status(401).json({ message: '未授权' })`。

**面试可答**：中间件和路由里第一个参数是 req、第二个是 res。从 req 上取 headers、query、body、params 做业务；用 res 设状态码和返回体。鉴权时从 req.headers 取 token，校验通过后挂到 req.user 给后面用。

---

### RESTful API

**是什么**：用 HTTP 方法表示对「资源」的操作：GET 获取、POST 创建、PUT 整体更新、PATCH 部分更新、DELETE 删除；URL 表示资源（如 `/tasks`、`/users/1`），而不是动词。

**特点**：语义清晰、无状态、便于缓存和统一鉴权。面试可说：我们接口按资源设计，任务列表 GET /tasks，创建任务 POST /tasks，更新 PUT /tasks/:id。

---

### JWT（JSON Web Token）

**是什么**：一种紧凑的、可携带签名的 token 格式，常用于「用户登录后标识身份」。结构一般为：Header.Payload.Signature，Payload 里可放 userId、过期时间等，服务端用密钥校验签名，不存 session。

**流程**：登录成功后端签发 JWT 给前端；前端存起来，之后请求在 Header 里带 token；后端鉴权中间件验签名、解出用户信息，合法则 next()，否则 401。

---

### RBAC（基于角色的访问控制，Role-Based Access Control）

**是什么**：通过「角色」分配权限：用户关联角色（如管理员、普通用户），角色关联可执行的操作或可访问的资源；鉴权时看「当前用户角色是否具备该权限」，而不是为每个用户单独配权限。

**面试可答**：我们管理后台有不同角色，菜单和接口根据角色显隐或鉴权，例如只有社区管理员能看审核菜单、能调审核接口，这就是 RBAC 思路。

---

### AJAX、fetch、Axios 与 HTTP 方法（GET / POST）

**AJAX**（Asynchronous JavaScript and XML）：指在**不刷新整页**的前提下，用 JavaScript **异步**向服务器发请求、拿数据并更新页面局部内容。早期常用 **XMLHttpRequest**（XHR），现在多用 **fetch**（原生）或 **Axios**（库）实现同样的「异步请求」能力，面试里说的「发请求、调接口」本质上都是在做 AJAX。

**fetch 用法**：浏览器原生 API，返回的 Promise **resolve 的是 Response 对象**（不是直接拿到 body）。  
- GET：`fetch(url)` 或 `fetch(url, { method: 'GET' })`，参数拼在 URL query。  
- POST：`fetch(url, { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(data) })`，数据放 body，需自己设 Content-Type 和 JSON.stringify。

**Response 返回值（常用属性和方法）**：  
- **response.ok**：布尔值，状态码在 **2xx 为 true**，其余为 false，常用来快速判断「请求是否成功」。  
- **response.status**：数字，HTTP 状态码，如 200、404、500。  
- **response.statusText**：状态文案，如 "OK"、"Not Found"。  
- **response.headers**：响应头，可用 `response.headers.get('xxx')` 取某个头。  
- **response.json()**：返回 Promise，resolve 为**解析后的 JSON 对象**，常用 `const data = await response.json()`。  
- **response.text()**：返回 Promise，resolve 为**响应体字符串**。

**重要**：fetch 只有**网络层失败**（断网、跨域被拦、CORS 错误等）才会 **reject**；**HTTP 4xx/5xx 仍会 resolve**，只是 response.ok 为 false、response.status 为对应状态码。所以业务里要自己判断：`if (!response.ok) throw new Error(...)` 或根据 `response.status` 分支处理（如 401 跳登录、404 提示不存在）。

**常见 HTTP 状态码**：**200** 成功、**201** 创建成功、**400** 请求参数错误、**401** 未授权（需登录）、**403** 禁止访问（无权限）、**404** 资源不存在、**429** 请求过于频繁、**500** 服务器内部错误、**503** 服务不可用（维护等）。面试可说：我们封装里 2xx 且业务 code 成功才当成功，401 清 token 跳登录，4xx 展示后端 message，5xx 统一提示服务器错误。

**Axios**：基于 Promise 的 HTTP 库，支持请求/响应拦截器、自动转 JSON、取消请求等。GET 用 `axios.get(url, { params: { a: 1 } })`，POST 用 `axios.post(url, data)`，统一在拦截器里带 token、处理错误，业务层写法更简洁。项目里管理后台用 Axios，小程序用 uni.request（无 fetch/Axios 环境）。

**fetch 与 Axios 对比**：

| 维度 | fetch | Axios |
|------|--------|--------|
| **来源** | 浏览器原生 API | 第三方库，需引入 |
| **返回值** | Promise resolve **Response 对象**，需再调 `.json()` 等拿 body | Promise resolve 的已是**响应体**（如 data），可配 `responseType` |
| **错误处理** | 只有网络错误才 reject，**4xx/5xx 仍 resolve**，要自己看 `res.ok` / `res.status` | 4xx/5xx 会 **reject**，可在 catch 或响应拦截器里统一处理 |
| **请求写法** | 要手写 method、headers、body，POST 需 `JSON.stringify(data)` | `axios.get(url, { params })`、`axios.post(url, data)`，自动带 JSON 头 |
| **拦截器** | 无 | **请求/响应拦截器**，统一加 token、统一处理错误、改 data |
| **取消请求** | 用 **AbortController** + `signal` | 用 **CancelToken** 或 **AbortController**（新版本） |
| **兼容性** | 现代浏览器原生支持，Node 18+ 内置 | 浏览器 + Node 都可用，老环境需 polyfill fetch 时 Axios 仍可用 |

**小结**：fetch 轻量、无依赖，但要自己处理 Response、状态码和 JSON 解析；Axios 业务层更省事，拦截器适合统一鉴权和报错，项目里需要「统一带 token、统一处理 401/4xx/5xx」时用 Axios 更合适。

**GET 与 POST**：GET 幂等、取数据，参数在 URL，可缓存；POST 非幂等、一般提交/创建，数据在 body。RESTful 里 GET 查、POST 增、PUT 整体改、DELETE 删。

**面试可答**：fetch 是原生 API，返回 Response 对象，要自己 `.json()`、判断 `res.ok`，4xx/5xx 不 reject；Axios 是库，直接拿 data、有拦截器、4xx/5xx 会 reject，适合统一鉴权和错误处理。我们管理后台用 Axios，小程序用 uni.request。详见上表。

### WebSocket（长连接 / 实时通信）【面试常问拓展】

**是什么**：一种在 **单个 TCP 连接上进行全双工通信** 的协议。浏览器和服务器之间建立一次 WebSocket 连接后，双方都可以**主动推送数据**，不必像 HTTP 那样「只能由客户端发起请求」。适合聊天、实时通知、看板数据刷新等场景。

**握手过程（简述）**：先发一次普通的 HTTP 请求（带 `Upgrade: websocket` 等头），服务器同意后返回 101 Switching Protocols，之后这个连接从 HTTP「升级」为 WebSocket，双方按 WebSocket 帧格式收发数据，不再走传统 HTTP 请求/响应。

**与轮询的区别**：  
- **短轮询**：客户端每隔 N 秒发一次 HTTP 请求问「有新消息吗」，实现简单但请求多、实时性一般。  
- **长轮询**：请求发出后服务器先挂起，有新数据才返回，减少空响应，但还是基于 HTTP，一次只回一批数据。  
- **WebSocket**：连接建立后**一直保持**，有新消息时服务器直接推给客户端，请求头开销小、实时性好，更适合高频或强实时场景。

**前端使用（浏览器 / 小程序 思路）**：  
- 浏览器：`const ws = new WebSocket('wss://example.com/ws'); ws.onopen = () => { ws.send(JSON.stringify({...})) }; ws.onmessage = (event) => { const data = JSON.parse(event.data); ... }`。  
- 小程序 / uni-app：用 `wx.connectSocket` 或 `uni.connectSocket` 建立连接，监听 `onOpen/onMessage/onClose/onError`，在页面销毁或应用进入后台时记得 `close`，避免泄漏。

**常见注意点**：  
- **重连**：网络断开或服务重启时要做心跳与重连逻辑。  
- **鉴权**：可以在 URL query 或子协议里带 token，或连接后先发一条带 token 的消息进行认证。  
- **降级方案**：业务对实时性要求不高时，可以先用轮询；需要更实时时再升级为 WebSocket（对应本题库 Q42 的思路）。

**面试可答**：HTTP 适合一次性请求/响应，轮询也能做「伪实时」，但请求多、延迟高；WebSocket 建立长连接、全双工通信，服务器可以主动推送，适合聊天、通知、看板。我们目前实时提醒可以先用轮询实现（见 Q42 的回答），后续有需要可以用 WebSocket 替代，注意心跳、重连和鉴权。

---

### 同源策略 与 跨域

**同源**：协议、域名、端口三者一致才算同源。  
**跨域**：前端脚本请求「不同源」的 URL 时，浏览器会限制（如拿不到响应体、或直接报错），这是浏览器的安全策略。

**常见解决方式**：后端 CORS 头（Access-Control-Allow-Origin 等）；开发时用 devServer 代理，让浏览器只请求同源；生产常用 Nginx 同域转发，前端只请求当前域名。

## 五、工程与部署相关

<a id="反向代理reverse-proxy"></a>
### 反向代理（Reverse Proxy）

**是什么**：服务器代替客户端去请求后端服务，再把结果返回给客户端。客户端只和代理通信，不知道后面有多少台、什么服务。

**用途**：隐藏真实后端、做负载均衡、统一配 SSL、做缓存等。Nginx 做反向代理时，根据路径把请求转发到 Node 等后端，并带上 Host、X-Real-IP 等头。

---

### 负载均衡（Load Balancing）

**是什么**：把多台后端服务器组成一个逻辑整体，入口（如 Nginx）按策略（轮询、权重、ip_hash 等）把请求分发给不同机器，分散压力、提高可用性。

---

### 前后端分离

**是什么**：前端只负责页面和交互、通过接口拿数据；后端只负责业务逻辑和数据库、提供 API。两者通过 HTTP/HTTPS 通信，可独立开发、部署、扩展。

**典型形态**：前端 SPA + 后端 RESTful API；静态资源可放 CDN 或 Nginx，接口单独域名或同域由 Nginx 转发。

---

### HTTP/2 与 HTTP/3 的区别（简述）

**HTTP/1.1**：每个请求一个 TCP 连接（或 Keep-Alive 复用），请求/响应是文本（或二进制 body），**队头阻塞**（同一连接上前一个请求没完，后面的要等）；多资源要开多个连接或排队。

**HTTP/2**：在**单条 TCP 连接**上**多路复用**（多个请求/响应流并行）、**二进制分帧**、**头部压缩**（HPACK），可**服务端推送**。仍基于 TCP，所以 TCP 层丢包重传时，整条连接上的流可能被阻塞（队头阻塞在 TCP 层）。

**HTTP/3**：基于 **QUIC**（跑在 **UDP** 上），每条流独立，**无 TCP 层队头阻塞**；支持 **0-RTT** 建连、连接迁移（如换 WiFi 不断连），更适合弱网、移动端。目前逐步推广，Nginx、CDN 等已支持。

**对比小结**：

| 维度 | HTTP/2 | HTTP/3 |
|------|--------|--------|
| 传输层 | **TCP** | **QUIC（UDP）** |
| 多路复用 | 有 | 有，且流之间更独立 |
| 队头阻塞 | TCP 层仍有 | 无（QUIC 流级） |
| 0-RTT / 连接迁移 | 无 | 支持 |
| 典型场景 | 当前主流，Nginx 配 `listen 443 ssl http2` | 弱网、移动端、追求更低延迟 |

**面试可答**：HTTP/2 多路复用、二进制分帧、头部压缩，仍基于 TCP；HTTP/3 基于 QUIC（UDP），无 TCP 队头阻塞、支持 0-RTT。我们部署时 Nginx 用 HTTP/2，若被问 HTTP/3 可答「基于 QUIC、更适合弱网，目前部分 CDN/浏览器已支持」。

### Vite 与 Webpack（打包/构建工具）【面试重点】

**作用**：把前端源码（Vue/React、ES Module、Sass 等）转成浏览器能运行的静态资源（HTML/JS/CSS），开发时提供热更新，生产时做打包、压缩、代码分割等。

**Webpack**：  
- **思路**：以**入口**为起点，根据 import/require 递归分析依赖，形成依赖图，再通过 **loader** 转译各类文件（如 babel-loader 转 JS、css-loader 处理 CSS），通过 **plugin** 做打包优化、注入环境变量、拷贝静态资源等，最后**一次性**输出 bundle（可做 code splitting 拆多 chunk）。  
- **开发**：启动时就要把整个依赖图建好并编译，项目大时**冷启动偏慢**；热更新只重编改动的模块，但仍有整图关系。  
- **特点**：生态成熟、可配置项多，适合复杂定制；Vue CLI 基于 Webpack。

**Vite**：  
- **思路**：开发阶段**不打包**，利用浏览器原生 **ES Module**，用 Koa 等起一个 dev server，按需把请求的模块做**即时编译**（如 .vue 用 esbuild 转成 JS），所以**冷启动快**；改哪个文件只编译哪个，**热更新也快**。  
- **生产**：用 **Rollup** 做打包，tree-shaking、代码分割、体积控制都较好。  
- **特点**：开发体验好、配置简单，Vue3 官方推荐；可配 `server.proxy` 解决开发跨域（如 /api 代理到后端）。

**对比小结**：

| 维度 | Webpack | Vite |
|------|---------|------|
| 开发 | 先打包再起服务，大项目冷启动慢 | 不打包，按需编译，冷启动快 |
| 热更新 | 只重编改动模块，但仍依赖整图 | 只编译当前请求的模块，更快 |
| 生产 | 自己打包，plugin 丰富 | 用 Rollup 打包，tree-shaking 好 |
| 配置 | 相对复杂，loader/plugin 多 | 开箱即用，配置少 |

**面试可答**：Webpack 是「先依赖分析再打包」，开发和生产都走打包流程，大项目冷启动慢；Vite 开发时不打包，用 ES Module + 按需编译，冷启动和热更新都快，生产用 Rollup 打包。Vue3 官方推荐 Vite，我们管理后台用 Vite，开发时用 proxy 把 /api 代理到 Node 解决跨域。简历写「熟悉 Vite、Webpack」时能说清二者差异和选用理由即可。

## 六、其他常问概念

<a id="git-常用操作面试常问"></a>
### Git 常用操作【面试常问】

**日常最常用**：  
- **查看状态**：`git status` 看工作区、暂存区。  
- **暂存与提交**：`git add .` 或 `git add 文件` 把改动加入暂存区；`git commit -m "提交说明"` 生成一次提交。  
- **推送与拉取**：`git push`（推送到远程，首次可 `git push -u origin main`）；`git pull` 拉取并合并（相当于 fetch + merge），常用 `git pull origin main`。  
- **拉取不合并**：`git fetch origin` 只拉远程更新到本地仓库，再手动 `git merge origin/main` 或 `git rebase origin/main`。

**分支**：  
- **查看**：`git branch` 看本地分支，`git branch -a` 看全部（含远程）。  
- **创建与切换**：`git checkout -b feature/xxx` 或 `git switch -c feature/xxx` 新建并切到该分支。  
- **切换已有分支**：`git checkout main` 或 `git switch main`。  
- **合并**：在目标分支（如 main）上执行 `git merge feature/xxx`，会多出一个合并提交；或用 **rebase**：在 feature 分支上 `git rebase main`，把本分支提交「挪到」main 最新之后，历史更线性（注意 rebase 会改写历史，已 push 的分支慎用）。

**冲突解决**：pull 或 merge/rebase 后若提示冲突，打开冲突文件会看到 `<<<<<<<`、`=======`、`>>>>>>>` 标记，按需求保留或修改内容并删掉标记，然后 `git add` 该文件，merge 时再 `git commit` 完成合并，rebase 时用 `git rebase --continue`，最后 `git push`。

**merge 与 rebase 区别**：**merge** 保留分支结构，多一个合并提交；**rebase** 把当前分支提交接到目标分支最新后，历史呈一条线、无合并节点。协作时常用 merge；自己整理提交历史时可用 rebase。已 push 的分支避免再 rebase，否则别人拉代码会乱。

**面试可答**：日常用 status、add、commit、push、pull；拉代码 pull 或 fetch+merge；切分支 checkout -b/switch -c；合并用 merge 或 rebase；冲突时改冲突文件、删标记、add 后 commit 或 rebase --continue 再 push。详见《吉利前端面试-基于简历与星火园帮》Q33～Q35。

<a id="localstorage-sessionstorage-cookies"></a>
### localStorage、sessionStorage 与 cookies 的区别【面试常问】

| 维度 | localStorage | sessionStorage | cookies |
|------|--------------|----------------|---------|
| **生命周期** | 持久化，除非主动删除或清缓存 | 仅当前标签页会话，关标签即清 | 可设过期时间（max-age/expires），或为会话级（关浏览器清） |
| **容量** | 一般约 5～10MB（按域名） | 同左 | 约 4KB/条，条数有限制 |
| **是否随请求发送** | 否 | 否 | 是，每次请求会带同域 cookie（可设 httpOnly 防 JS 读） |
| **典型用途** | 持久化用户偏好、token、离线数据 | 单页会话内临时数据、表单草稿 | 服务端会话标识、登录态（常配合 httpOnly）、跨子域共享 |
| **API** | getItem / setItem / removeItem / clear | 同左 | document.cookie 读写，或服务端 Set-Cookie |

**面试可答**：localStorage 和 sessionStorage 都是前端存键值对，不随请求发；localStorage 持久、sessionStorage 关标签就没了。cookie 容量小、会随请求带到服务端，适合会话/登录态，可设 httpOnly 防 XSS 偷 token。我们项目里 token 和用户信息用 localStorage（或 uni.setStorageSync）做持久化，配合 Vuex；若后端用 cookie 存 session，前端一般不直接改 cookie，由服务端 Set-Cookie。

### uni-app 概览（跨端 / 小程序）【简历常问】

**是什么**：基于 Vue（也支持其他框架）的**跨端开发框架**，一套代码可编译到微信/支付宝/百度等小程序、H5、App（iOS/Android）。用 Vue 语法写页面和逻辑，通过 **条件编译** 和 **uni 统一 API** 适配多端差异。

**和原生微信小程序的区别**：原生要写 WXML/WXSS、小程序自己的 API（wx.xxx）；uni-app 用 **Vue 单文件组件**（.vue）、Vue 语法，API 用 **uni.xxx**（如 uni.request、uni.getStorageSync、uni.login），编译时转成对应端。**好处**：会 Vue 即可上手、一套代码多端发、后续扩展 H5/App 方便；**注意**：小程序环境没有 window/document，部分浏览器 API 和第三方库不可用，需用条件编译或 uni API 替代。

**条件编译**：用 `#ifdef MP-WEIXIN`、`#ifdef H5`、`#endif` 等在代码里区分平台，只编译进当前端，避免在小程序里用 H5 专有 API 报错。例如小程序专用逻辑包在 `#ifdef MP-WEIXIN` 里，H5 用 axios 时可在 `#ifdef H5` 里引入。

**常用 uni API**：**uni.request** 发请求（替代 axios/fetch，小程序端用这个）、**uni.getStorageSync / uni.setStorageSync** 本地存储、**uni.login** 微信登录拿 code、**uni.uploadFile** 上传文件、**uni.showToast** 提示等。请求封装时在拦截器里统一带 token、处理 401，和 Axios 思路一致。

**多端差异注意点**：小程序无 window/document、部分 CSS 不支持或表现不同、rpx 与 px、分包配置（pages.json 的 subPackages）、真机与开发者工具差异、需在微信公众平台配 request/uploadFile 合法域名等。

**面试可答**：uni-app 是 Vue 语法写、一套代码编译多端（小程序/H5/App）；和原生比用 Vue 组件 + uni.xxx API，条件编译区分平台；我们项目用 uni-app 做星火园帮小程序，请求用 uni.request、存储用 uni.setStorageSync、登录用 uni.login 拿 code 给后端换 openid；遇到 H5 正常小程序报错时用条件编译或换 uni API。详见《吉利前端面试-基于简历与星火园帮》Q5、Q21～Q24。

### document 与 DOM 常见操作（getElementById、addEventListener 等）

**DOM**：浏览器把 HTML 解析成的节点树，通过 **document** 和节点上的方法可以查、增、删、改节点以及绑定事件。

**查节点**：  
- `document.getElementById('id')` 按 id 取单个元素（id 唯一）。  
- `document.querySelector('选择器')` / `document.querySelectorAll('选择器')` 按 CSS 选择器取，前者取第一个，后者取全部。  
- `document.getElementsByClassName('类名')`、`document.getElementsByTagName('标签名')` 取集合（注意返回的是类数组、会动态变化）。  
- 从某节点出发：`node.children`（仅元素子节点）、`node.childNodes`（含文本等）、`node.parentNode`、`node.nextSibling` / `previousSibling`。

**增 / 删节点**：  
- `document.createElement('div')` 创建元素；`parent.appendChild(子节点)` 在父节点末尾插入；`parent.insertBefore(新节点, 参考节点)` 在参考节点前插入。  
- `parent.removeChild(子节点)` 或 `节点.remove()` 删除节点。

**改内容与属性**：  
- `节点.textContent`、`节点.innerText`（文本）、`节点.innerHTML`（含 HTML，慎用防 XSS）。  
- `节点.setAttribute('attr', 'value')`、`节点.getAttribute('attr')`。  
- `节点.classList.add/remove/toggle('类名')` 增删切换 class。

**事件**：  
- `节点.addEventListener('事件名', 回调, 可选配置)` 绑定；`节点.removeEventListener('事件名', 同一引用回调)` 解绑（需保留回调引用以便移除）。  
- 常见事件：click、input、submit、scroll、resize、keydown 等。

**面试可答**：查用 getElementById、querySelector/querySelectorAll；增删用 createElement、appendChild、removeChild/remove；改用 textContent、innerHTML、setAttribute、classList；事件用 addEventListener/removeEventListener。Vue/React 里多数用数据驱动，直接操作 DOM 少，但图表、地图等要拿 ref 取真实 DOM 再调库。详见《吉利前端面试-基于简历与星火园帮》Q16-12。

### Element Plus 概览（Vue3 后台 UI 库）

**是什么**：基于 **Vue 3** 的桌面端**组件库**，是 Element UI 的 Vue3 版本，提供表格、表单、分页、弹窗、菜单、布局等现成组件，适合管理后台、中后台系统。

**和 Element UI 的关系**：Element UI 面向 Vue 2；**Element Plus** 面向 Vue 3，API 和用法类似，迁移成本低。若简历同时写 Vue2/Vue3 和「Element」，面试可能问「用过 Element UI 还是 Element Plus」——管理后台用 Vue3 就是 Element Plus。

**常用组件**：**el-table**、**el-form**、**el-pagination**、**el-dialog**、**el-button**、**el-input**、**el-menu**、**el-card**、**el-message** / **el-notification** 等。按需引入可减小打包体积；可配主题色、暗色模式。

**项目里怎么用**：在 main.js 里 `app.use(ElementPlus)` 全量或按需注册；表格用 el-table + :data 绑定数据、el-pagination 分页；表单用 el-form + 校验；覆盖样式时用类名提高权重，少用全局 !important。我们星火园帮管理后台用 Vite + Vue3 + Element Plus 做仪表盘、任务管理、权限等页面。

**面试可答**：Element Plus 是 Vue3 的组件库，和 Element UI 对应 Vue2；我们管理后台用表格、表单、分页、弹窗、菜单等，和 Vue2 的 Element UI 用法类似。详见《吉利前端面试-基于简历与星火园帮》Q6、Q6-1。

### script 的 async 与 defer（HTML 脚本加载）

都是用在 `<script src="...">` 上，控制**下载**和**执行**时机，避免阻塞 HTML 解析。

| 写法 | 下载 | 执行 | 是否阻塞解析 | 执行顺序 |
|------|------|------|--------------|----------|
| 无属性 | 立即、阻塞解析 | 下载完立即执行 | 阻塞，执行完才继续解析 | 按书写顺序 |
| **async** | 与解析并行下载 | 下载完**立即执行**（可能打断解析） | 执行时阻塞 | **不保证**顺序，谁先下完谁先执行 |
| **defer** | 与解析并行下载 | 等 **HTML 解析完** 再按顺序执行 | 不阻塞解析 | **保证**按书写顺序执行 |

**使用场景**：  
- **defer**：依赖 DOM 或按顺序依赖的脚本（如业务主包），希望「不阻塞首屏、但执行顺序稳定」。  
- **async**：独立脚本、不依赖 DOM 也不依赖其他脚本（如统计、广告），谁先下完谁先跑即可。  
- 无属性：老写法，一般放 body 底部减少阻塞；若放 head 且无 async/defer 会明显拖慢首屏。

**面试可答**：defer 是异步下载、解析完再按顺序执行，不阻塞解析，适合主业务脚本；async 是异步下载、下完就执行，不保证顺序，适合独立脚本。我们打包后的入口脚本常用 defer 或放 body 底，保证 DOM 就绪再执行。

### 组件化 与 模块化

**组件化**：把 UI 拆成可复用的「组件」（如按钮、列表项、表单块），每个组件有自己的结构、样式、逻辑，便于维护和复用。  
**模块化**：把代码按功能拆成独立模块（文件），通过 import/export 组织，避免全局污染、依赖关系清晰。

**结合星火园帮的组件化实践**：  
- **小程序端**：把「一条任务摘要」抽成 **TaskCard** 组件，列表页、详情页、我的发布等多处用 `v-for + TaskCard`，只传 task 和少量 props（如是否显示操作按钮），样式和展示逻辑集中在一个组件里，改一处到处生效；**发布按钮、自定义导航栏**也做成公共组件，多页复用，避免重复写。  
- **管理后台（Vue3 + Element Plus）**：页面按功能拆成视图组件（如 LoginView、DashboardView、TaskManager），表格、表单、分页用 el-table、el-form、el-pagination 等业务组件；公共的请求封装、工具函数放在独立模块（如 `@/common/request.js`），通过 import 引入，属于**模块化**。  
- **拆组件的原则**：高复用（多处用同一块 UI）、单一职责（一个组件只负责一块展示或交互）、便于维护（改样式/逻辑只改一个文件）。面试时可以说：我们星火园帮里任务卡片、导航栏、发布按钮都做了组件化，列表页只负责拉数据和分页，渲染交给 TaskCard，这样结构清晰、复用率高。详见《吉利前端面试-基于简历与星火园帮》Q12。

**面试可答**：组件化是把 UI 拆成可复用组件，模块化是用 import/export 组织代码。我们项目里小程序有 TaskCard、导航栏、发布按钮等公共组件，后台有按页面拆的视图组件和 Element Plus 业务组件，请求和工具单独成模块，便于维护和复用。

### ORM（Object-Relational Mapping）

**是什么**：用面向对象的方式操作数据库，把表映射成「模型」，用模型的方法做增删改查，而不是手写 SQL 字符串。如 Sequelize：`Task.findAll({ include: [User] })` 代替写 join SQL。

**好处**：代码可读性高、易维护；换数据库时改动相对小；防 SQL 注入等。

---

### 高可用（High Availability）

**是什么**：系统尽量少宕机、少不可用时间。手段包括：多实例部署 + 负载均衡、健康检查、自动重启、数据库主从/备份等。面试时说「稳定后端」「高可用 API」可结合这些点简单说。
