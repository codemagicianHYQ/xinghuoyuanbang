# 星火园帮：从前端小程序发起到后端返回的完整工作流程

本文档按「一次请求」从用户操作到数据库再回到前端的顺序，说明整条链路。

---

## 一、整体架构（一眼看懂）

```
┌─────────────────┐     HTTPS      ┌─────────────┐     HTTP      ┌──────────────────┐
│  微信小程序      │  ──────────►  │   Nginx     │  ──────────►  │  Node 后端        │
│  (星火园帮)     │  请求 API     │  反向代理   │  转发到 1112  │  (Express)        │
│  uni-app        │               │  443/80     │               │  server.js        │
└─────────────────┘               └─────────────┘               └────────┬─────────┘
                                                                           │
                                                                           ▼
                                                                  ┌──────────────────┐
                                                                  │  路由 → 控制器    │
                                                                  │  → 服务 → 模型   │
                                                                  │  → MySQL/Redis  │
                                                                  └──────────────────┘
```

---

## 二、前端：小程序里「发请求」是怎么发生的

### 1. 统一配置与入口

- **接口根地址**在 `星火园帮/common/config.js` 里：
  ```js
  const baseURL = "https://xinghuoyuanbang.top/campushelper/api/v1";
  ```
- 页面里**不直接写完整 URL**，而是用封装好的 **`request()`**（在 `common/request.js` 里）：
  - 传入 `url: "/auth/wechat-login"`、`method`、`data` 等；
  - `request.js` 里会拼成：`baseURL + url` → 即 `https://xinghuoyuanbang.top/campushelper/api/v1/auth/wechat-login`。
- 部分上传接口在页面里写了**完整 URL**（如上传头像、任务图片等），本质上仍是请求同一域名下的 `/campushelper/api/v1/upload/...`。

### 2. request 封装做了哪些事

在 **`common/request.js`** 里，每次调用 `request(options)` 时大致会：

1. **拼 URL**：若 `options.url` 不是以 `http` 开头，则用 `baseURL + options.url`。
2. **带 token**：从本地存储取 `userAuthToken_xh`，放到请求头（如 `token: "Bearer xxx"`）。
3. **发请求**：通过 **`uni.request`**（uni-app 对微信 `wx.request` 的封装）发 HTTPS 请求。
4. **统一处理响应**：
   - 2xx 且业务 `code === 0`：`resolve(res.data)`，页面拿到的就是后端返回的 data。
   - 401：清 token、提示登录过期或弹窗引导重新登录。
   - 400/404/503 等：根据接口做提示（如接单失败、维护中等）。
5. **可选**：请求队列、简单 GET 缓存、token 续期（根据响应头 `x-renewed-token`）等。

所以：**前端「发请求」= 在页面/ store 里调 `request({ url, method, data })`，最终由 `request.js` 用 `uni.request` 发到 `https://xinghuoyuanbang.top/campushelper/api/v1/...`。**

## 三、网络层：请求怎么到你的服务器

1. 用户手机上的**微信**执行小程序代码，向 `https://xinghuoyuanbang.top/...` 发 **HTTPS** 请求。
2. 请求先到 **xinghuoyuanbang.top** 所在机器的 **Nginx**（监听 443）。
3. Nginx 根据 **location** 规则转发：
   - 配置里有：`location /campushelper/api/ { proxy_pass http://127.0.0.1:1112/campushelper/api/; ... }`
   - 所以请求被转到本机 **1112 端口**，路径不变，仍是 `/campushelper/api/v1/...`。
4. 本机 **1112 端口** 上跑的是 **Node 进程**（如 PM2 启动的 `server.js`），即你的 **Express 后端**。

总结：**小程序 → HTTPS → Nginx(443) → 反向代理 → Node(1112) → Express。**

---

## 四、后端：Express 收到请求之后

### 1. 请求进到 Express 的顺序

在 **`星火园帮后台管理系统/server.js`** 里，中间件和路由大致顺序是：

1. **安全与日志**
   - `helmet`、可疑请求检测、请求日志（如 `requestLogger`）等。
2. **CORS**
   - 校验请求来源是否在白名单（如 `https://xinghuoyuanbang.top`、本地开发域名等）。
3. **静态资源**
   - 如 `/用户头像`、`/学生证` 等映射到本地或本地上传目录（实际文件多在 COS，这里多为兜底）。
4. **特殊接口优先**
   - 例如 **微信支付回调**：`POST /campushelper/api/v1/pay/notify` 需要先取 raw body，所以单独写在前面，再用 `next()` 交给后续逻辑。
5. **Body 解析**
   - `express.json()`、`express.urlencoded(...)`，之后路由里才能用 `req.body`。
6. **挂载业务路由**
   - **小程序用**：`app.use("/campushelper/api/v1", apiLimiter, mainRoutes);`
   - **管理后台用**：`app.use("/admin/api/v1", ... admin.routes);`
   - 所以所有「校园帮」接口的前缀都是 **`/campushelper/api/v1`**。

### 2. 路由是怎么对上「小程序请求」的

- **mainRoutes** 来自 **`routes/index.js`**。
- 在 `routes/index.js` 里：
  - 例如：`router.use("/auth", authLimiter, authRoutes);`
  - 那么完整路径就是：**`/campushelper/api/v1` + `/auth` + 子路径**。
- 所以小程序里：
  - `request({ url: "/auth/wechat-login", method: "POST", data })`
  - 实际请求：`POST https://xinghuoyuanbang.top/campushelper/api/v1/auth/wechat-login`
  - 在 Express 里会匹配到 **`auth.routes.js`** 里的 **`router.post("/wechat-login", ...)`**。

其他模块同理：

- `url: "/tasks/xxx"` → `routes/task.routes.js`
- `url: "/users/me"` → `routes/user.routes.js`
- `url: "/upload/avatar"` 或完整 URL 里带 `/campushelper/api/v1/upload/avatar` → `routes/upload.routes.js`
- 支付、钱包、聊天、反馈、社区、考试资料等，都在 `routes/index.js` 里挂载了对应子路由，路径与小程序里 `request` 的 `url` 一一对应。

### 3. 单条请求在后端内部的流程（以登录为例）

以 **微信登录** 为例，从进入 Express 到返回：

1. **进入路由**  
   `POST /campushelper/api/v1/auth/wechat-login` → `mainRoutes` → `auth.routes.js` 的 `router.post("/wechat-login", ...)`。

2. **控制器/逻辑（在 auth.routes.js 或抽到 controller）**
   - 从 `req.body` 取 `code`、`userInfo`、`version`。
   - 用 `code` 调 **微信接口** `jscode2session` 换 `openid`（及 session_key）。
   - 用 `openid` 在 **User 表** 里查：有则更新信息，无则创建用户。
   - 生成 **JWT**（如 `jwt.sign({ id: user.id, ... }, secret, { expiresIn })`），写入 cookie 或只通过响应体返回。

3. **返回**
   - `res.json({ success: true, accessToken, user: { id, nickname, avatarUrl, ... } })`。
   - 前端 `request.js` 里收到 2xx 和 `code === 0`，把 `accessToken`、`user` 存到本地（如 `uni.setStorageSync`），后续请求在 header 里带这个 token。

4. **需要鉴权的接口**
   - 路由上会挂 **`verifyToken`**（或类似）中间件，从 header 里取 token，校验 JWT，把用户信息挂到 `req.user`，再进控制器；失败则 401，前端就会走「登录过期」逻辑。

其他接口（任务、上传、支付等）同理：**路由 → 中间件（鉴权、限流等）→ 控制器/服务 → 查库或调外部 API → res.json(...)**。

## 五、数据与存储

- **用户、任务、订单、资源等**：MySQL，通过 **Sequelize** 访问（`models/` 里定义表结构，控制器里调 `User.findByPk`、`Task.create` 等）。
- **会话/限流/缓存等**：若配置了 **Redis**，会在对应服务里用（如 session、限流计数）。
- **上传文件**：先到 Node（`upload.routes.js`），再传到 **腾讯云 COS**，接口返回的 URL 是 COS 或自定义域名（如 `files.xinghuoyuanbang.top`）；小程序里拿这个 URL 显示图片。

## 六、从「用户点登录」到「页面跳转」串起来（示例）

1. 用户在小程序里点「微信登录」。
2. 小程序调 `wx.login()` 拿临时 `code`，再调 `request({ url: "/auth/wechat-login", method: "POST", data: { code, userInfo, version } })`。
3. `request.js` 拼出 `https://xinghuoyuanbang.top/campushelper/api/v1/auth/wechat-login`，用 `uni.request` 发 POST。
4. 请求经 Nginx 转发到本机 1112，进入 Express。
5. Express 匹配到 `mainRoutes` → `auth.routes.js` 的 `/wechat-login`，用 code 换 openid，查/建用户，生成 JWT，`res.json({ success: true, accessToken, user })`。
6. 小程序端 `request.js` 收到响应，存 token 和 user，`resolve(data)` 给登录页。
7. 登录页或 Vuex 里根据返回结果跳转首页（如 `uni.switchTab` 到首页）。

之后用户做任何需要登录的操作（如拉任务列表、发消息），同样是：**页面调 `request({ url: "/tasks/...", ... })` → 同一套 Nginx → Node → 路由 → 控制器 → 数据库 → res.json → 前端收到数据并渲染。**

## 七、小结表（方便查阅）

| 环节           | 位置/文件 | 说明 |
|----------------|-----------|------|
| 前端接口根地址 | `星火园帮/common/config.js` | `baseURL = https://xinghuoyuanbang.top/campushelper/api/v1` |
| 前端发请求     | `星火园帮/common/request.js` | 拼 URL、带 token、`uni.request`、统一处理 2xx/4xx/5xx |
| 页面/业务调用  | 各页面、store | `request({ url: "/auth/wechat-login", method, data })` |
| 域名与转发     | Nginx     | `xinghuoyuanbang.top` 443 → `127.0.0.1:1112`，路径 `/campushelper/api/` |
| 后端入口       | `server.js` | 中间件顺序、CORS、body 解析、挂载 `/campushelper/api/v1` → mainRoutes |
| 路由挂载       | `routes/index.js` | `/auth`、`/tasks`、`/users`、`/upload`、`/pay` 等子路由 |
| 具体接口实现   | `routes/*.routes.js`、`controllers/`、`services/` | 鉴权、调微信/支付、查库、写库、返回 JSON |
| 数据存储       | MySQL（Sequelize）、Redis、腾讯云 COS | 用户/任务/订单等表；上传文件在 COS |

按上述顺序，从「小程序里一次 `request`」到「Nginx → Express → 路由 → 控制器 → 数据库 → 再回到前端」的完整路径就都串起来了。
