## 四、星火园帮项目深挖

### 4）请介绍一下星火园帮项目

**参考回答：**

星火园帮是一个校园全场景生活服务平台，主要解决校园内信息不对称和学生多样化需求的问题。  
项目包含三个部分：用户端小程序、管理后台和 Node 后端服务。用户端使用 uni-app + Vue，实现任务发布、接单、资源互换、二手市场、个人中心等模块；管理后台使用 Vue3 + Vite + Element Plus，用于管理用户、订单、任务和内容；后端使用 Node.js + Express + Sequelize + MySQL 提供 RESTful API。

我的工作覆盖前端页面开发、统一请求封装、登录鉴权、接口联调、后台管理页面和线上部署。

### 5）你在星火园帮里最核心的贡献是什么？

**参考回答：**

我认为核心贡献有三点：  
第一，完成了小程序端核心业务页面，包括任务发布、任务列表、个人中心、登录等模块。  
第二，封装了统一请求层，处理 baseURL、token、错误码、401 登录失效等逻辑，让页面代码更干净。  
第三，完成了项目上线相关工作，包括 Nginx 反向代理、HTTPS 配置和前后端分离部署。

### 6）你的小程序请求到后端完整链路是什么？

**参考回答：**

前端页面调用封装好的 `request()`，比如请求 `/auth/wechat-login`。  
`request()` 会拼接统一的 baseURL，并带上 token，然后通过 `uni.request` 发起 HTTPS 请求。  
请求先到域名对应的 Nginx，Nginx 根据 `/campushelper/api/` 路径反向代理到本机 Node 服务 1112 端口。  
Express 收到请求后进入路由、中间件、控制器或服务层，最终通过 Sequelize 查询 MySQL 或访问 Redis/COS，再把 JSON 返回给前端渲染。

### 7）你项目里的 Nginx 反向代理怎么用？

**参考回答：**

我的项目里 Nginx 主要做三件事：  
第一，对外提供统一 HTTPS 入口，用户访问的是域名和 443 端口。  
第二，把 `/campushelper/api/` 这类 API 请求转发到本机 Node 服务，比如 `127.0.0.1:1112`。  
第三，托管管理后台的静态资源，并配置 SSL 证书保证传输安全。

这样前端只需要维护稳定的域名和接口前缀，不需要关心后端服务端口；后端迁移或重启时，也更容易通过 Nginx 做统一管理。

### 8）你怎么处理登录鉴权？

**参考回答：**

小程序端先调用 `wx.login()` 拿 code，再请求后端登录接口。  
后端用 code 换 openid，查询或创建用户，然后生成 JWT 返回前端。前端把 token 存到本地，后续请求通过 header 携带。  
后端通过鉴权中间件校验 token，校验成功后把用户信息挂到请求对象上；如果 token 失效，返回 401，前端统一清理登录态并引导重新登录。

### 9）你怎么做接口错误处理？

**参考回答：**

我会分三层处理：网络错误、HTTP 状态码、业务 code。  
例如 401 做登录失效处理，5xx 提示服务异常，网络超时提示用户重试。对于提交类操作，会增加 loading 和防重复提交，避免弱网下用户连续点击造成重复数据。

## 五、Vue / Element-UI / Antdv / 中后台问题

### 10）你用 Vue 做过哪些页面？

**参考回答：**

在星火园帮里，小程序端使用 uni-app + Vue，管理后台使用 Vue3 + Vite + Element Plus。  
后台页面包括用户管理、任务管理、订单管理、内容审核等，主要涉及表格、表单、弹窗、分页、搜索筛选和权限控制。

### 11）Element Plus 和 Antdv 这类 UI 组件库你怎么理解？

**参考回答：**

这类组件库主要解决中后台开发中重复 UI 的问题，比如表格、表单、弹窗、分页、上传、菜单等。  
使用时不能只会复制组件，而要理解它们的数据绑定、事件回调、插槽、自定义渲染和表单校验。  
虽然我项目里主要使用 Element Plus，但 Antdv 的使用思路类似，都是围绕组件属性、事件、插槽和表单模型来开发。

### 12）如果让你用 Antdv 做一个用户管理页，你怎么设计？

**参考回答：**

我会拆成四块：搜索表单、数据表格、分页器、新增/编辑弹窗。  
页面加载时请求用户列表，搜索条件变化后重置页码并重新请求；表格操作列提供编辑、禁用、删除；弹窗表单做字段校验，提交后刷新列表。  
接口层会统一封装，避免在页面里直接写完整请求逻辑。

### 13）Vue2 和 Vue3 你怎么区分？

**参考回答：**

Vue2 主要使用 Options API，响应式基于 `Object.defineProperty`；Vue3 支持 Composition API，响应式基于 Proxy。  
Vue3 在逻辑复用、类型支持和大型项目组织上更灵活。  
我的小程序端更多是 Vue 语法和 uni-app 结合，后台则用 Vue3 + Element Plus，更接近现代中后台开发。

### 14）组件化开发你怎么理解？

**参考回答：**

组件化不是把页面随便拆小，而是按职责拆分。  
比如一个管理列表页可以拆成搜索区、表格区、弹窗表单、接口层和状态层。这样页面结构清晰，后续新增字段或复用弹窗时成本更低。

## 六、AI 在项目中的使用（重点）

### 15）你平时怎么使用 Cursor、Claude Code、Codex、Trae 这类 AI 工具？

**参考回答：**

我会按任务类型区分使用：  
Cursor 更适合在 IDE 内结合上下文做代码修改、组件补全和重构；  
Claude Code 更适合复杂问题拆解、跨文件影响分析和方案评审；  
Codex 更适合根据明确任务生成代码初稿或测试用例；  
Trae 这类 AI IDE 更适合快速搭建页面、理解项目结构和做局部迭代。

我的原则是：AI 负责提效，人负责判断。AI 可以生成初稿，但最终要经过我自己的代码 review、联调和测试。

### 16）你在星火园帮项目中具体怎么用 AI？

**参考回答：**

我主要用在五个环节：  
第一，需求拆解。把一个页面需求拆成组件、接口、状态和异常分支。  
第二，页面初稿。让 AI 生成基础布局和交互骨架，比如表单、列表、弹窗、分页。  
第三，请求封装。让 AI 辅助整理错误码处理、token 注入和 401 逻辑。  
第四，bug 排查。把报错信息、接口返回和相关代码片段给 AI，让它给排查路径。  
第五，测试和回归。让 AI 生成回归清单，比如登录、提交、防重、弱网、空态。

### 17）你用 AI 做 UI 和交互是怎么做的？

**参考回答：**

我不会让 AI 直接“一键生成上线页面”，而是先让它辅助做结构化初稿。  
例如一个任务列表页，我会先让 AI 帮我拆信息层级：筛选区、任务卡片、状态标签、分页加载、空态和错误态。  
然后用 Cursor 生成组件骨架，再根据项目已有样式和 uni-app 规范调整。  
交互部分会重点处理加载状态、上拉加载、提交防重、接口失败重试、登录失效跳转。最后通过真机和接口联调验证。

### 18）为什么公司会关心你会不会用 AI？

**参考回答：**

因为前端工作里有很多重复性任务，比如表单、表格、接口封装、样式调整、bug 定位和测试用例。  
会用 AI 的开发者可以更快完成初稿，把时间放在需求理解、边界处理和质量把控上。  
但前提是不能盲信 AI，否则会带来隐藏 bug 和安全风险。

### 19）你使用 AI 的注意点有哪些？

**参考回答：**

第一，不上传生产密钥、用户隐私、公司内部敏感代码。  
第二，不让 AI 直接决定权限、支付、删除数据等高风险逻辑。  
第三，所有 AI 生成代码都要 review，重点看是否符合现有架构、是否破坏接口兼容、是否漏掉异常分支。  
第四，关键功能要联调和测试，不能只看代码“像是对的”。

### 20）如果 AI 生成的代码有问题，你怎么处理？

**参考回答：**

我会先看 diff，确认问题出在需求理解、上下文不足还是模型生成错误。  
如果是上下文不足，我会补充接口结构、组件规范和不可变约束再让它重试。  
如果是关键逻辑错误，我会手动修正，并把这类规则沉淀到后续 prompt 或团队规范里。

### 21）你怎么写 Prompt？

**参考回答：**

我一般按“目标 + 上下文 + 约束 + 输出格式 + 验收标准”写。  
例如：现在要改 request 封装，只允许修改 `request.js`，保留原来的调用方式，新增 401 统一处理，要求列出影响点和回归清单。  
这样 AI 输出会更稳定，也更容易检查。

### 22）请讲一下你的 AI 工作流

**参考回答：**

我的 AI 工作流分六步：  
第一，需求澄清，让 AI 帮我列用户故事、边界和验收点。  
第二，方案比较，让 AI 给出最小改动方案和长期优化方案。  
第三，生成初稿，用 Cursor/Codex 生成组件、接口、测试草稿。  
第四，人工收口，检查代码风格、业务逻辑、权限边界。  
第五，联调测试，验证正常态、空态、异常态和权限态。  
第六，复盘沉淀，把高频任务整理成 prompt 模板或 checklist。

### 23）你如何衡量 AI 提效？

**参考回答：**

我不会只看写代码速度，而会看三个指标：  
第一，需求到可联调的时间是否缩短；  
第二，返工率和线上 bug 是否减少；  
第三，重复代码和低级错误是否下降。  
如果只是写得快但问题更多，那不算真正提效。

## 七、AI 基础概念可能追问

### 24）什么是 Agent？

**参考回答：**

Agent 可以理解为面向目标的 AI 执行体。它不是只回答问题，而是会感知上下文、拆解任务、选择工具、执行动作、观察结果并继续调整。  
它的核心闭环是：感知、规划、行动、反馈、再规划。

### 25）Agent 和普通 AI 问答有什么区别？

**参考回答：**

普通问答主要给建议，Agent 更强调执行任务。  
比如普通 AI 可以告诉我怎么修 bug，而 Agent 可以读取代码、定位文件、修改代码、运行测试，并根据结果继续调整。  
但 Agent 权限更大，所以要限制工具权限和操作范围。

### 26）什么是 Function Calling？

**参考回答：**

Function Calling 是让模型按结构化参数调用外部函数或工具。  
例如用户说“查一下杭州今天的天气”，模型不是直接编答案，而是生成参数调用天气接口。  
在前端场景里，可以把自然语言转成查询条件、表单字段或操作指令，但必须做 schema 校验和权限控制。

### 27）什么是 MCP？

**参考回答：**

MCP 可以理解为模型连接外部工具和资源的标准协议。  
它让 AI 以统一方式访问文件、数据库、浏览器或设计工具，避免每个工具都单独写一套适配逻辑。  
工程落地时要重点关注权限、工具 schema 和调用审计。

### 28）什么是 RAG？

**参考回答：**

RAG 是检索增强生成，也就是先从可信知识库里检索相关内容，再让模型基于这些内容回答。  
它适合公司内部文档、项目知识库、接口文档问答等场景。  
相比直接问大模型，RAG 更可追溯，也能减少知识过期和幻觉。

### 29）什么是 Skills？

**参考回答：**

Skills 可以理解为可复用的 AI 工作能力包，里面包含任务步骤、约束、输出格式和注意事项。  
它比单次 prompt 更像团队 SOP。比如可以沉淀“接口联调排查 Skill”“前端页面生成 Skill”“Code Review Skill”。

## 八、前端基础与页面开发问题

### 30）你如何实现一个复杂页面布局？

**参考回答：**

我会先拆结构：页面容器、头部筛选、内容列表、操作区、弹窗或底部按钮。  
布局上优先使用 Flex 和 Grid，移动端关注适配、安全区、滚动区域和按钮热区。  
然后再处理状态：加载、空态、错误态、禁用态，保证页面不是只有静态效果。

### 31）你怎么处理移动端 H5 适配？

**参考回答：**

常用方式包括弹性布局、百分比、rpx/rem、媒体查询和安全区适配。  
同时要关注点击区域、输入框弹起、滚动穿透、图片比例和不同机型表现。

### 32）你怎么做列表性能优化？

**参考回答：**

先做分页或上拉加载，避免一次渲染大量数据。  
图片使用懒加载，频繁触发的滚动事件做节流。  
如果数据特别大，可以考虑虚拟列表。小程序里还要注意 setData 或响应式数据更新不要过大。

### 33）你怎么处理表单校验？

**参考回答：**

我会把表单校验分为前端体验校验和后端最终校验。  
前端校验包括必填、格式、长度、枚举值等，提交时做 loading 和防重；后端返回错误时映射成用户能理解的提示。

## 九、数据库与接口联调

### 34）你掌握哪些基础数据库操作？

**参考回答：**

常见 CRUD、分页、排序、条件查询都可以。  
在星火园帮里，我通过 Sequelize 操作 MySQL，比如按 openid 查询用户、创建任务、更新订单状态、分页查询列表。

### 35）为什么前端实习也要懂数据库？

**参考回答：**

前端不一定直接写复杂 SQL，但懂数据库能帮助理解接口返回、分页逻辑、状态流转和慢接口原因。  
比如列表慢不一定是前端渲染问题，也可能是后端查询没命中索引。

### 36）你怎么和后端联调接口？

**参考回答：**

先确认接口文档，包括 URL、方法、参数、返回结构、错误码。  
前端先用 mock 跑通页面状态，再切真实接口。  
联调时重点看字段命名是否一致、空数据如何返回、错误码怎么处理、权限失败怎么提示。
